# ＝LOVEイントロクイズ（＝LOVE Intro Quiz）

アイドルグループ **＝LOVE（イコールラブ）** の曲で遊べる、ブラウザ／スマホ（PWA）向けの音楽クイズゲームです。イントロを聴いて曲名を当てるクイズを中心に、タイムアタック・オンライン対戦・ライブのコール練習などができます。＝LOVE が好きで、自分でも遊びたいと思って作りました。フレームワークは使わず、HTML / CSS / JavaScript だけで作っています。

## 作ったきっかけ

自分も ＝LOVE のファンで、曲を覚えたりライブを楽しんだりするときに「こんな機能があったら便利だな」と思うことがありました。ふつうのイントロクイズだと ＝LOVE の曲だけで深く遊べるものが無かったので、それなら自分で作ろうと思って作り始めました。

## 主な機能

### 遊ぶ
- **イントロクイズ**：イントロを聴いて曲名を 4 択で答える。答えが速いほど高得点で、ランク（S/A/B/C）や自己ベストがつきます。
- **タイムアタック ＋ ランキング**：全問正解までのタイムを競います。通常クイズの記録も参加できる1つのランキングに反映されます。
- **オンライン対戦**：ルームを作って相手が参加 → 3・2・1 → 同じ問題で対戦（Firebase を使って時刻を合わせています）。
- **ライブコール**：曲に合わせて「次のコール」を表示します。ライブ前の練習にも使えます。
- ほかに、ランダム再生クイズ／歌詞クイズ／オリジナル問題作成／苦手曲モード／ローカル対戦。

### 記録・育成
- プレイ履歴（全モードまとめて）・自己ベスト・平均回答時間
- ランキング（ルール・出題数・カテゴリ別）
- 称号 17 種／苦手曲の自動収集（4 モードの結果を合わせて判定）

### 音楽・ファン
- 収録 81 曲の一覧・検索・試聴／お気に入り／プレイリスト／オフライン連続再生
- 推し設定／フレンド（公開プロフィール）／メンバー・作品・年表・ライブ（公演一覧）

（全部の機能は、起動したあとにアプリ内で見られます。）

## 工夫したところ

1. **カラオケ表示のズレを直した** — スマホで遊んでいて、一時停止して再開するとコールの表示がズレることに気づきました。その場で秒数をずらすのではなく、再生時間と補正値を別々に管理するように直しました。
2. **苦手曲モードを作り直した** — 最初は最後まで遊んだ分しか苦手曲に反映されませんでした。途中でやめた回答も1問ごとに記録するようにして、3回以上答えて正答率が50%未満の曲を自動で苦手曲に入れるようにしました。
3. **ランキングを作り直した** — 最初はタイムアタックだけのランキングでしたが、通常クイズの記録も参加できる1つのランキングにしました。今までの記録が消えないように気をつけて直しました。
4. **ライブで困ったことを機能にした** — 初めてのライブだとコールのタイミングが分かりません。そこで、曲に合わせて次のコールを表示する機能を作りました。

## 技術構成

- HTML / CSS / JavaScript（フレームワーク・ライブラリは使わず、ES Modules で分割）
- PWA：`manifest.json` + Service Worker（`sw.js`）で、オフライン起動やホーム画面へのインストールに対応
- Firebase Realtime Database ＋ 匿名認証（オンライン対戦・ランキング・フレンドの公開プロフィール）
- IndexedDB（音源・歌詞・コールを端末の中に保存＝配らないようにするため）、localStorage（履歴・苦手曲・お気に入りなど）
- Web Audio API（イントロ再生・効果音）

### 簡単なアーキテクチャ

```
端末（ブラウザ / PWA）── これだけでも遊べる
  ├ Web Audio API  … イントロ再生・効果音
  ├ localStorage   … 履歴・苦手曲・お気に入り・設定
  ├ IndexedDB      … 音源・歌詞・コール（端末の中に保存）
  └ Service Worker … オフライン起動・インストール
        │  匿名認証でつなぐ（オンラインのときだけ同期）
        ▼
Firebase Realtime Database（クラウド）
  └ オンライン対戦・ランキング・フレンドの公開プロフィール
```

## 自分がやったこと / AI の使い方

- **自分（制作者）**：どんなゲームにするかの企画、モードやルールを決めること、画面の見た目や使いやすさ、スマホで実際に遊んでの確認、使いにくい所やバグを見つけること、どう直すか決めて直ったか確認すること。
- **AI（Claude Code）**：調べもの、コードを書く手伝い、テストの手伝い、作業の自動化。

コードを書くところは AI を使いましたが、**何を作るか・どこをどう直すかは自分で決めています。** 大学の授業で HTML や CSS の基礎は学びました。約 1 か月で 173 commits、後半はほとんどが一度作った機能の作り直しでした。

## テスト

- 自分で書いたテストが **51 ファイル・1,511 アサーション** あります。オンラインの同期や苦手曲の判定、ランキングなど、間違えると気づきにくい部分を確認しながら作りました。

## ローカルでの起動方法

ES Modules を使っているため、`index.html` をダブルクリックして直接開いても動きません（ブラウザの制限のため）。簡単なローカルサーバー経由で開いてください。

- **VSCode の「Live Server」拡張機能**：このフォルダを開き、`index.html` を右クリック →「Open with Live Server」。

## 音源について

このアプリは「実在する ＝LOVE の曲のイントロを当てる」ことを目的にしていますが、著作権のことがあるので、本物の曲の音源はこのリポジトリには入れていません。

- 曲データ（`js/data/songs.js`）には曲名や選択肢などの情報を持たせていますが、イントロの音源そのものはコードに含めていません。
- 音源は、遊ぶ人が自分の端末で選んだ mp3 を、ブラウザの IndexedDB（端末の中の保存領域）に読み込む方式です。読み込んだ音源はその端末の中にだけ残り、サーバーや GitHub には送られません。
- `assets/audio/local/` は開発中に音源を一時的に置く場所で、`.gitignore` で除外していて GitHub にはアップロードされません。
