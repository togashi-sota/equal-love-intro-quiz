## 4. UIデザインの方向性

### 配色・世界観
- ＝LOVEのCDジャケット（プールモチーフ・レモン/シトロンモチーフ）を参考に、Artifactでモックアップを見せながら本人と合意形成した独自配色。
- **メイン**：パステルピンク・白／**サブ**：パステルブルー／**アクセント**：レモンイエロー
- コンセプトは「もし＝LOVEの公式イントロクイズゲームがあったら」。かわいい系をベースにしつつ、上品さ・アイドルらしい華やかさも意識。
- 音楽ゲームらしさを出すモチーフ：音符（星を添えた特別仕様アイコン）、キラキラ、レコード盤、イコライザー、ステージライト（にじむ光の玉）、ガラス風カード。

### 画面ごとの演出強度（意図的に差をつけている）
- **スタート画面・結果画面**：演出は華やかめ。背景装飾（ギンガムチェック模様・光の玉・ぼかしたレコード盤・キラキラの粒）をしっかり効かせる。
- **クイズ画面**：「プレイ中に一番長く見る画面」という理由で、背景演出を意図的に控えめにしている。実装は`body[data-screen="quiz"]`でCSS変数（`--pattern-opacity`等）を上書きする方式（`js/screens.js`の`showScreen()`が`body`の`data-screen`属性を更新）。カードのガラスの透け感も弱め、文字のコントラストを優先。

### 主要なUIコンポーネント（実装済み）
- **ガラス風カード**（`.game-frame`）：半透明＋backdrop-filterのぼかし。上端にピンク→ブルー→イエローの三色リボンライン。
- **背景演出**：`.bg-decorations`という`position: fixed; overflow: hidden;`の入れ物にまとめてあり、画面に固定・クリップされる（ページ本体のスクロールに一切影響しない設計。詳細は12章のバグ修正履歴参照）。
- **タイトル周り**：パステルカラーのレコード盤が回転するロゴ、星を添えた特別仕様の音符アイコン、「MUSIC INTRO QUIZ」の小さなラベルチップ、イコライザー風の演出バー。
- **ランクバッジ**（結果画面の主役）：文字は常に単色でくっきり読めるようにし、特別感は円形メダルの縁取り・光・アイコンで段階的に表現する設計。
  - S：太い金縁＋金色グラデーション＋強い光＋王冠＋星2つ＋光が走る演出
  - A：白縁＋濃いピンク＋白文字＋星1つ＋内側の二重リングとハイライトで金属的な質感
  - B：二重リング（銀メダル風）＋パステルブルー＋控えめな光
  - C：薄い一重の実線の縁取り（元は点線だったが「無効状態」に見えるため変更）＋ラベンダーグレー＋装飾なし
  - CSSは`css/style.css`の「===== ランクバッジ =====」セクション、クラスは`rank-s`/`rank-a`/`rank-b`/`rank-c`を`main.js`がランクに応じて1つ付け替えるだけの構造（将来、称号・コメントを追加しやすいよう意図的にシンプルな入れ子構造にしてある）。
- **自己ベストチップ**（スタート画面）：選択中の出題数・カテゴリに対応する自己ベストを表示。「🏆 5問・全曲　ベスト 49点」のように、条件部分は控えめな色・点数部分は強調色。記録がなければ「記録なし」＋グレー系の見た目になる（`is-empty`クラス）。ラジオボタン切り替え時・スタート画面復帰時にリアルタイム更新。
- **結果画面のボタン**：主ボタン「もう一度挑戦する」（ピンク塗りつぶし）／副ボタン「タイトルに戻る」（白背景＋ピンク縁取り）の縦2段構成（詳細は10章）。

## 5. 採用している設計・アーキテクチャ

- **フレームワーク不使用**。素のHTML/CSS/JavaScript（ES Modules）。
- 状態管理は`state.js`の`gameState`という1つのオブジェクトに集約し、**変更は必ず`state.js`の関数経由で行う**というルール。
- 各JSファイルは役割ごとに分割されており、`import`/`export`で繋いでいる（一覧は6章）。
- コードコメントは日本語。「何をしているか」だけでなく「なぜそうしているか」を書く方針。
- 曲データ（`songs.js`）とゲームロジックは完全に分離。曲を増やす作業は`songs.js`を編集するだけで完結する。
- CSSの色・間隔・アニメーション速度などはCSS変数（`:root`）に集約。新しい画面固有の調整は`body[data-screen="..."]`でのCSS変数上書きというパターンを使う（クイズ画面の演出を控えめにする際に確立した手法）。
- **拡張しやすさを見越した設計判断（すでに実施済み）**
  - 画面の追加（曲一覧画面など）は、`js/screens.js`の`SCREEN_ELEMENTS`という対応表に1行足すだけで済む。
  - 出題数のラジオボタンも、`index.html`に`<label>`を1つ増やすだけで選択肢を増減できる。
  - 結果画面のランクバッジ（`.rank-badge`）は、称号・コメントを追加したくなったら中に要素を1つ足すだけで済む構造。
  - 出題数・カテゴリを指定してクイズを開始する処理は`js/main.js`の`beginQuiz()`に共通化済み（10章参照）。
- **ES Modules撤廃（方法A）は、今後の機能追加フェーズも含めて全体がほぼ完成した最後に行う方針で確定済み**。理由：機能追加の途中でモジュール構成を変えると、実装・管理がかえって複雑になるため（本人の判断）。
  - 手順（着手時の想定）: (1) `<script type="module">`と各ファイルの`import`/`export`を撤廃し、IIFEなどで名前空間を区切った普通の`<script>`構成に書き換える (2) ユニットテストで計算ロジックの回帰がないか確認 (3) Live Serverで通常通り動作確認 (4) スマホの`file://`で直接開いてオフライン動作を確認
  - **実施前に必ずバックアップを取る**（フォルダコピー、またはGitでの記録）。
  - PWA/Service Worker化も検討したが、Service Workerは`https`または`http://localhost`でしか動かないという制約があり、「PCがサーバー・スマホがLAN経由でアクセス」という今の構成とは相性が悪いため不採用と判断済み。

## 8. 音源の入手ルート・取り込み手順

### ファイル命名規則
- ファイル名（拡張子を除く）は、`songs.js`の該当曲の`id`と完全に一致させる（`js/audio.js`が`` `${AUDIO_BASE_PATH}${song.id}.mp3` ``という形でパスを組み立てているため）。
- 例: 「＝LOVE」→`love.mp3`、「探せ ダイヤモンドリリー」→`sagase-diamond-lily.mp3`。曲名を省略せずローマ字化するのが基本方針。

### 入手ルート（3種類、確立済み）

| ルート | 説明 | 状態 |
|---|---|---|
| CDリッピング | 外付けドライブ＋Windows Media Playerで取り込み | メイン。19シングル分＋アルバムをカバー |
| moraでの音声購入 | 配信限定曲をDRMフリーのmp3として個別購入 | 内緒バナシ・宝物はグリーン・君だけの花道・おかえり花便り |
| moraでの動画購入＋VLC変換 | ビデオ限定販売の曲を、DRMなしを確認の上VLCで音声抽出 | 拝啓貴方様（アルバムTYPE-B限定曲）・866（2周年記念曲）・Overture |
| ~~Blu-rayリッピング~~ | **不採用**。AACSコピーガードの回避は私的利用でも違法 | 使用しない方針で確定 |

### 取り込みフロー（毎回この手順）
1. CDの場合: 外付けBD/DVDドライブ＋Windows Media Player（従来版）で取り込み（形式はMP3、コピー防止は「追加しない」を選択）
2. moraの場合: 「ミュージック」形式ならそのままmp3としてダウンロード。「ビデオ」形式の場合は、まず普通の動画プレーヤーで再生できる（＝コピー保護なし）ことを確認してから、VLCの「メディア→変換/保存」で「Audio - MP3」に変換
3. 取り込んだファイルを、`songs.js`の`id`に合わせてリネーム
4. `assets/audio/local/`に移動

## 9. これまで決めたゲームルール

### スコアリング（`score.js`）
段階式（ティア）方式。出題開始（＝曲が実際に鳴り始めた瞬間）からの経過秒数に応じて、1問10点満点：

| 経過秒数 | 得点 |
|---|---|
| 3秒以内 | 10点 |
| 5秒以内 | 9点 |
| 8秒以内 | 8点 |
| 12秒以内 | 7点 |
| 20秒以内 | 6点 |
| 30秒以内 | 5点 |
| 45秒以内 | 4点 |
| 60秒以内 | 3点 |
| 60秒超 | 2点 |
| 不正解・スキップ・答えを見る | 0点 |

- 制限時間による強制終了は**廃止**。曲は最後まで自動再生され続けるが、曲が終わっても問題自体は終了せず、回答/スキップ/答えを見るのいずれかをプレイヤーが選ぶまで待ち続ける。
- ランクは「1問10点満点 × 出題数」に対する達成率で判定: 90%以上=S、70%以上=A、50%以上=B、それ未満=C。
- **無音の頭出し（`introLeadInSec`）について**：曲の頭に無音区間がある場合（例: 拝啓貴方様、約4.4秒）、`js/audio.js`が再生開始時にその秒数分シークしてから再生する。これにより無音を聞かせずに済み、`score.js`の採点ロジックはこの値を一切受け取らない（採点tierのルール自体は変更なし）。2026-07-27に「採点時に差し引く」方式から「再生位置を頭出しする」方式に変更した（元の方式だと無音を聞かされる体験自体は解決しなかったため）。

### 回答時間の記録（`state.js`・`main.js`）
- 曲が実際に鳴り始めた瞬間（`playing`イベント）から回答確定までのミリ秒を、`gameState.answerLog`の各要素に`elapsedMs`として記録（丸めていない生の値）。採点には使わず、結果画面の内訳表示（「⏱◯.◯秒」バッジ、表示時だけ小数第1位に丸め）と将来の記録機能のために使う。
- 計測開始点は、再生を試みた直後の暫定値→`playing`イベントで正確な値に上書き、という2段構えにしてあり、超高速回答でも必ずデータが記録される（`markPlaybackStarted()`を2箇所から呼ぶ設計）。

### カテゴリ絞り込み（`quiz.js`の`filterSongsByCategory`）
- `"title-track"`: 表題曲のみ
- `"title-and-group"`: 表題曲＋全員曲（ユニット曲を除く）
- `"all"`: 絞り込みなし（ユニット曲・特別枠のOvertureも含む全曲）
- 4択クイズを作るには最低4曲必要（`MIN_SONGS_REQUIRED`）。足りない場合はエラーメッセージを表示。

### 4択の選択肢生成（`quiz.js`の`generateChoices`）

### スキップ／答えを見るの挙動の違い

- **答えを見る**: 0点記録、正解の曲名を表示 →「次へ」ボタンで進む（スキップより1テンポ遅い）

## 12. 既知の技術的注意点（再発防止メモ）

### `hidden`属性とCSSの`display`指定が競合するバグ（2026-07-27発見・修正済み）

**症状**: 自己ベストを更新していないのに「🎉新記録！」バッジが表示され続ける不具合が発生。`js/main.js`に一時的な`console.log`を仕込んで調査したところ、判定ロジック（`isNewRecord`）自体は完全に正しく動いていた。原因はJSではなくCSS側だった。

**原因**: HTML標準の`hidden`属性は、本来ブラウザの初期スタイル（`[hidden] { display: none; }`、詳細度が低い）によって非表示になる。しかし`#new-record-badge`にチップ風の見た目を整える際、`display: flex;`をIDセレクタで指定していたため、**詳細度の高いこのCSSが`[hidden]`の`display: none`を上書きしてしまい、JSが`hidden = true`にしても実際には非表示にならない**状態になっていた。同じ原因のバグが`.secondary-button`（スキップ・答えを見るボタン）にも存在し、あわせて修正した。

**修正方法**: `hidden`属性と、`display`を明示的に指定するCSS（`display: flex`など）を同じ要素に使うときは、必ず`セレクタ[hidden] { display: none; }`という上書き用のルールを一緒に用意する。

**今後の注意点**: 新しいUIパーツに`hidden`属性でのJS制御（表示/非表示の切り替え）を組み込む際は、そのパーツのCSSに`display`の指定（`flex`・`grid`・`inline-flex`など、`none`以外の値）があるかどうかを必ず確認し、あれば`[hidden]`用の上書きルールを追加すること。`.primary-button[hidden]`・`#quiz-actions[hidden]`・`#new-record-badge[hidden]`・`.secondary-button[hidden]`にはすでに同様のルールがあり、これがお手本になる。
