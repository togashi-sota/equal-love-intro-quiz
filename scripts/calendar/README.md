# ＝LOVEカレンダーの自動取得（本人用の説明）

公式サイト（https://equal-love.jp/schedule/）の **SCHEDULE** から、予定の **日付・種類・タイトル・時間・放送局・出演・会場・公式の URL だけ** を集めて、
アプリの「＝LOVEカレンダー」と質問AIに出します。YouTube 出演図鑑・＝LOVE 最新情報の自動更新と同じ公開の仕組みに乗っていますが、手順は別です。

**新しい設定・キー・アカウントは要りません。**（公式サイトの公開のページを読むだけ）

---

## 全体の形
```
毎日 3時台（GitHub の定期実行）・毎週月曜（Apps Script の合図）・master への push
        ▼
GitHub Actions「Deploy to GitHub Pages」
  1. YouTube のデータ（前のまま）
  2. ＝LOVE 最新情報（前のまま）
  3. ＝LOVEカレンダー（scripts/calendar/refresh-calendar.mjs）← 失敗してもほかの手順と公開は止めない
     - 月のカレンダーのページを6回（先月〜4か月先）＋近い予定（60日先まで）の詳細を最大25回。3秒ずつ空ける
     - 前のデータ ＝ git の土台（data/calendar/official-schedule-seed.json）＋ 公開中のデータ ＋ 長く残す記録（枝 calendar-data）。足していくだけで消さない
     - data/official-schedule.json を作り、Pages に載せる。作れなかった日は、公開中のデータ → 記録 → 土台 の順に前のものを入れ直す
  4. 長く残す記録（別のワークフロー .github/workflows/calendar-archive.yml。公開のあとに動く）
     - 予定に本当の変化があった日だけ、枝 calendar-data の calendar/official-schedule-archive.json を書き直してコミット
     - master には書かない。公開のワークフローは読むだけのまま。記録の予定を1件も減らさない（減るデータでは書かない）
        ▼
アプリ「＝LOVEカレンダー」：開いたときにデータを読む。最終更新の日付を出す。8日以上取れていなければ「更新が止まっています」
```
- ふだんのアクセスは1日に6〜10回くらい（新しい予定の詳細があるときだけ増える。上限40回）
- 費用：無料（GitHub Actions は公開リポジトリなら無料）

## 取るもの・取らないもの
| 取る | 取らない |
|---|---|
| 予定の ID・日付（カレンダーで置かれている日＝開催日・放送日・発売日）・公式のカテゴリ・タイトル（表示のまま） | 本文・画像・番組の外のリンク |
| 詳細の見出し【時間】【放送局】【出演】【会場】【放送日】の値だけ | 見出しの無い文章 |
| 関連メンバー（タイトルの「※名前」・【出演】に ＝LOVE のメンバーの名前があるときだけ） | 名前が書いていないメンバーの推定・≠ME/≒JOY のメンバー |
| 中止・延期（公式のタイトルに書いてあるときだけ）・日時の変更（公式の予定表で日付・時間が変わったとき） | 「見えなくなった」だけで中止にすること |

- 発表日（NEWS の日付）はカレンダーに使わない（発表日と開催日を取り違えないため。NEWS はカレンダーに入れていない）
- 深夜の番組（24:45〜25:15）は、公式の放送日のまま載せる。画面には「実際は翌日 0:45〜」も添える
- 過去の分（2017年9月〜）は、2026-11-24 に手元で1回だけ読んで土台にした（110か月・110回のアクセス・3秒ずつ）

## 予定が消えない理由（2026-11-25）
| 起きること | どうなるか |
|---|---|
| 毎日の更新 | 前のデータ（3か所）に足すだけ。消さない |
| 新しい版の公開（Pages の作り直し） | 公開中のデータが欠けても、記録の枝と土台から全部引き継ぐ |
| 公式サイトに繋がらない日 | 前のデータのまま公開し直し、「取得できませんでした」と出す |
| データファイルが欠けた・壊れた | 公開中のデータ → 記録 → 土台 の順に入れ直す。壊れたものは公開しない |
| 前の版に戻した | 記録の枝は master と別なので残る。カレンダーのある版に戻せば、全部戻る |
| 何か月も更新が止まった | 公開中のデータ・記録はそのまま。アプリは「更新が止まっています」と出す |

## 規約・負荷
- robots.txt（2026-11-24 確認）：`User-agent: *` だけで、禁止の場所は無い
- 公式サイトから利用規約・転載の決まりのページは見つからなかった（FAQ にも無い）。事実の情報だけを、出典のリンク付きで出す
- 名乗る：User-Agent に「EqualLoveIntroQuiz-CalendarCheck/1.0（個人のファンアプリ・アプリの URL）」
- 3秒空ける・20秒で打ち切る・5xx のときだけ1回やり直す・読む URL は SCHEDULE の月のページと詳細のページだけ

## 困ったとき
| 届いたもの | 意味 | すること |
|---|---|---|
| GitHub の Issue「＝LOVEカレンダーの自動取得：確認が必要です」の「公開しなかった理由」 | 公式サイトが落ちていた・形が変わった | 1回だけなら様子を見る。続くなら Claude に「scripts/calendar の読み方を直して」と頼む |
| 同じ Issue の「見当たらなくなった予定」 | 公式の予定表から予定が消えた | 公式サイトで確かめる。アプリでは消さずに「公式の予定表に見当たらない」と出している |
| 同じ Issue の「知らないカテゴリ」 | 公式のカテゴリが増えた | アプリでは「その他」に入れている。必要なら js/calendarCore.js の SITE_CATEGORIES に足す |
| アプリに「更新が止まっています」 | 8日以上、取得できていない | GitHub の［Actions］で「Deploy to GitHub Pages」が動いているか見る |

- 同じ中身の知らせは、Issue に何度も書かない（前の知らせと同じなら書かない）
- 手で動かす：GitHub の［Actions］→「Deploy to GitHub Pages」→［Run workflow］
- 手元で試す（ネットを使わない）：`node scripts/calendar/refresh-calendar.mjs --trigger push --from-html <保存した HTML のフォルダ>`
- 土台を新しくする（手元・ときどき）：`node scripts/calendar/refresh-calendar.mjs --backfill 2026-11:2026-12` のあと `git add data/calendar` でコミット
