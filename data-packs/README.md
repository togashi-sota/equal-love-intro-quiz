# 追加データパック 作業フォルダ

「＝LOVEイントロクイズ」の新曲（21枚目以降）を、実際のアプリへ安全に取り込むための作業場所です。
このフォルダに置いた音源・歌詞などの実データは、**`.gitignore` で除外されているため GitHub には一切公開されません**（`data-packs/21st/` の中身が対象。この `README.md` と `manifest.template.json` だけは、実データを含まない安全な説明・雛形なので公開されます）。

読み込み機構そのものの仕様は `js/dataPackImport.js` を参照してください。

## フォルダ構成

```
data-packs/
  README.md                 … このファイル（公開）
  manifest.template.json    … マニフェストの雛形・記入例（公開、実データなし）
  21st/                      … 21stシングル用の作業フォルダ（非公開）
    .gitkeep
    manifest.json            … 実際に使うマニフェスト（後述の手順で自動生成する）
    <songId>.mp3              … 音源ファイル
    <任意のファイル名>.json    … 歌詞データ（1曲1ファイル）
    calls.json                … コールデータ（任意、PCのコールエディターで書き出したもの）
    call-guides.json          … コールガイドデータ（任意、PCのコールガイドエディターで書き出したもの）
```

**ポイント：サブフォルダに分けず、1つのフォルダに全部まとめて置いてください。**
アプリの読み込みボタンは、ブラウザの標準的な「複数ファイル選択」ダイアログを使っており、
サブフォルダの中身までは自動的に読み込めない仕組みのためです（`webkitdirectory` は使っていません）。

## ファイル名のルール

- **音源**：`<songId>.mp3` という名前にしてください（例：`yume-no-tsuzuki.mp3`）。曲IDは `js/data/songs.js` に登録済みのものを使います。ファイル名の拡張子を除いた部分がそのまま曲IDとして扱われます。
- **歌詞**：ファイル名は自由です（中身の `songId`（または `song_id`）フィールドで曲を判別します）。形式は `js/lyricsStorage.js` が扱う内部形式（`{ songId, lines: [{ line, text, start, end }, ...] }`）、または解析パイプライン（`tools/lyrics-pipeline`）が出力する外部形式（`song_id` を使う形式）のどちらでも構いません。
- **コール／コールガイド**：PCの `dev/callEditor.html` ／ `dev/callGuideEditor.html` の「書き出す」機能で出力したJSONファイルを、そのままこのフォルダに置いてください。ファイル名は自由です（中身の `type` フィールドで判別します）。
- **マニフェスト**：`manifest.json` という名前にしてください（このファイル自体は Claude が生成します。手作業は不要です）。

## 使い方（詳しい手順は本人とのチャットのやり取りを参照）

1. このフォルダ（`data-packs/21st/`）に、音源・歌詞などの実ファイルを置く。
2. Claude に「ファイルを置きました」と伝える。
3. Claude が中身を確認し、`manifest.json` を自動生成する。
4. アプリのホーム画面 →「データ管理」→「追加データパックを読み込む」から、このフォルダの中身をまとめて選択する。

**著作権保護のため、このフォルダの実データ（音源・歌詞本文・コール本文）は絶対に Git へコミットしない・GitHub へ push しないでください。** `.gitignore` で自動的に除外されるようになっていますが、`git add -A` のような一括コマンドを不用意に使わないよう注意してください。
