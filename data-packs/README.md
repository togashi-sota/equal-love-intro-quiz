# 追加データパック 作業フォルダ

「＝LOVEイントロクイズ」の新曲を、実際のアプリへ安全に取り込むための作業場所です。
このフォルダに置いた音源・歌詞などの実データは、**`.gitignore` で除外されているため GitHub には一切公開されません**（`data-packs/`直下の各シングル用サブフォルダ〈`21st/`・`22nd/`…どんな名前でも自動的に対象〉と`full/`の中身が対象。この `README.md` と `manifest.template.json` だけは、実データを含まない安全な説明・雛形なので公開されます）。

読み込み機構そのものの仕様は `js/dataPackImport.js` を参照してください。

## 運用ルール（本人決定、2026-08-27）

新曲の配布は、**「full.zip（その時点での全曲入り）＋ シングルごとの差分ZIP（21st.zip・22nd.zip・23rd.zip…）を積み重ねていく方式」**に統一する。

- **`full.zip`**：新規ユーザー向け。これまでの全曲が入っている。新しいシングルが出るたびに、そのつど最新の全曲入りへ作り直す（既存曲＋新曲すべて）。
- **`<シングル名>.zip`**（例：`21st.zip`）：既存ユーザー向け。そのシングルの新曲だけが入っている。今持っているデータには一切触れず、追加するだけ。

新しいシングルを追加するときの手順：

1. 音源（`<songId>.mp3`）を`assets/audio/local/`へ、歌詞タイミングJSON（`<songId>-timing.json`）があれば`assets/lyrics/local/`へ置く（今までどおりの個人アーカイブ）。
2. `js/data/songs.js`へ新曲を登録する。
3. `data-packs/<シングル名>/`（例：`data-packs/22nd/`）フォルダを作り、そのシングル分の`manifest.json`・音源・歌詞を用意する（詳しい手順は本人とのチャットのやり取りを参照。`packKind: "incremental"`で、`songIds`にはそのシングルの曲だけを入れる）。
4. `cd dev && python generate_full_pack.py` を実行し、`data-packs/full/`を最新の全曲入りへ作り直す。
5. `cd dev && python package_zip.py <シングル名>` と `python package_zip.py full` の両方を実行し、`data-packs/<シングル名>.zip`・`data-packs/full.zip`を作る（このスクリプトは`data-packs/`直下にフォルダさえあれば、どんな名前でもZIP化できる。シングルが増えるたびにスクリプト自体を書き換える必要はない）。
6. 新規ユーザーには最新の`full.zip`を、既存ユーザーには自分がまだ持っていないシングル分の差分ZIPを配布する。

## 過去に配布したデータの間違いを、後から安全に修正版へ差し替える方法（2026-08-29追加）

「追加データパックを読み込む」は、既にこの端末にあるデータを壊さないよう、通常は
**曲ごとに「まだ持っていないデータだけ」を自動で追加し、既に持っているデータはスキップする**
（新曲追加パックを何度読み込んでも、既存データが上書きされて消える事故が起きないようにするため）。

そのため、「配布済みのデータに間違いがあり、後から正式な修正版を配ってもう一度読み込んでもらう」
場合（実例：『僕のヒロイン』に『ヒロインズ』の歌詞が誤登録されていた事故の修正）は、
そのままでは「もう持っている」と判定されて修正版が反映されない。これを安全に解決するのが
`data-packs/corrections-manifest.json`。

手順：

1. 修正済みの実データ（歌詞txt再修正→`tools/lyrics-pipeline`で再解析、等）を用意する（今までどおり）。
2. `data-packs/corrections-manifest.json`の該当する項目（`lyrics`/`audio`/`calls`/`callGuides`）へ、
   その曲IDを追記する（例：`"lyrics": ["boku-no-heroine"]`）。このファイルは実データを含まない
   単なるID一覧なので、Gitで公開してよい（`data-packs/*/*`パターンには一致しないため、
   このファイル自体は`.gitignore`の対象外）。
3. `cd dev && python generate_full_pack.py`を実行する。指定した曲IDが、
   `data-packs/full/manifest.json`の`corrections`項目へ自動的に反映される。
4. `cd dev && python package_zip.py full`で`full.zip`を作り直す。
5. 新しい`full.zip`を配布し、「追加データパックを読み込む」からもう一度読み込んでもらう。
   `corrections`に載っている曲だけは、既にこの端末にあっても正式な修正版として上書きされる
   （それ以外の曲は今までどおり、既存データがあればスキップされたまま変わらない）。

**自分のiPhone/端末でも、同じ手順（新しいfull.zipを読み込み直す）で修正版へ更新できる。**
1曲だけをすぐに直したい場合は、「歌詞データをインポート」の単体インポート画面から
修正版の歌詞JSON（`assets/lyrics/local/<songId>-timing.json`）を選んでもよい
（こちらは元々、常に無条件で上書きする仕様のため、corrections登録を待たずに使える）。

## フォルダ構成

```
data-packs/
  README.md                 … このファイル（公開）
  manifest.template.json    … マニフェストの雛形・記入例（公開、実データなし）
  21st/                      … 21stシングル用の作業フォルダ（非公開）
  22nd/                      … 22ndシングル用の作業フォルダ（非公開、以降も同じ形で増えていく）
    .gitkeep
    manifest.json            … 実際に使うマニフェスト（後述の手順で自動生成する）
    <songId>.mp3              … 音源ファイル
    <任意のファイル名>.json    … 歌詞データ（1曲1ファイル）
    calls.json                … コールデータ（任意、PCのコールエディターで書き出したもの）
    call-guides.json          … コールガイドデータ（任意、PCのコールガイドエディターで書き出したもの）
  full/                      … 全曲パック用の作業フォルダ（非公開、generate_full_pack.pyが自動生成）
```

**ポイント：サブフォルダに分けず、1つのフォルダに全部まとめて置いてください。**
アプリの読み込みボタンは、ブラウザの標準的な「複数ファイル選択」ダイアログを使っており、
サブフォルダの中身までは自動的に読み込めない仕組みのためです（`webkitdirectory` は使っていません）。

## ファイル名のルール

- **音源**：`<songId>.mp3` という名前にしてください（例：`yume-no-tsuzuki.mp3`）。曲IDは `js/data/songs.js` に登録済みのものを使います。ファイル名の拡張子を除いた部分がそのまま曲IDとして扱われます。
- **歌詞**：ファイル名は自由です（中身の `songId`（または `song_id`）フィールドで曲を判別します）。形式は `js/lyricsStorage.js` が扱う内部形式（`{ songId, lines: [{ line, text, start, end }, ...] }`）、または解析パイプライン（`tools/lyrics-pipeline`）が出力する外部形式（`song_id` を使う形式）のどちらでも構いません。
- **コール／コールガイド**：PCの `dev/callEditor.html` ／ `dev/callGuideEditor.html` の「書き出す」機能で出力したJSONファイルを、そのままこのフォルダに置いてください。ファイル名は自由です（中身の `type` フィールドで判別します）。
- **マニフェスト**：`manifest.json` という名前にしてください（このファイル自体は Claude が生成します。手作業は不要です）。

## 使い方（詳しい手順は上の「運用ルール」・本人とのチャットのやり取りを参照）

1. そのシングル用のフォルダ（例：`data-packs/22nd/`）に、音源・歌詞などの実ファイルを置く。
2. Claude に「ファイルを置きました」と伝える。
3. Claude が中身を確認し、`manifest.json` を自動生成する。
4. Claude が`full.zip`・そのシングルの差分ZIPの両方を作り直す。
5. アプリのホーム画面 →「データ管理」→「追加データパックを読み込む」から、ZIPを選択する（新規ユーザーは`full.zip`、既存ユーザーは差分ZIPだけでよい）。

**著作権保護のため、このフォルダの実データ（音源・歌詞本文・コール本文）は絶対に Git へコミットしない・GitHub へ push しないでください。** `.gitignore` で自動的に除外されるようになっていますが、`git add -A` のような一括コマンドを不用意に使わないよう注意してください。
